# speedtest

Консольный замер скорости скачивания: делает **N последовательных** HTTP-запросов
к заданному URL, дожидается полного тела ответа на каждый и печатает среднее
время запроса, суммарный объём скачанного и скорость.

Зависимостей нет — только стандартная библиотека Python 3.8+.

## Запуск

```bash
python3 speedtest.py <url> [опции]

На Windows бинарник обычно называется python или py:

py speedtest.py <url> [опции]

Флаг	            По умолчанию	Что делает
-n, --n	            10	            Сколько последовательных запросов сделать
--max-retries	    5	            Максимум ретраев на один запрос (429/5xx/сетевые ошибки)
--delay	            0.0	            Пауза в секундах между успешными запросами
--max-backoff	    30.0	        Потолок экспоненциального бэкоффа между ретраями
--max-retry-after	30.0	        Если сервер просит ждать Retry-After больше — не слушаемся (см. ниже)

# Speedtest-эндпоинт, который не лимитирует — лучший выбор для демо
python3 speedtest.py https://speed.hetzner.de/100MB.bin

# «Тяжёлая картинка» из тз, но CDN отдаёт 429 на серию — нужна пауза
python3 speedtest.py https://upload.wikimedia.org/wikipedia/commons/3/3f/Fronalpstock_big.jpg --delay 1.5 -n 5

# Меньше запросов, больше ретраев
python3 speedtest.py https://proof.ovh.net/files/100Mb.dat -n 5 --max-retries 8

Как это работает
Для каждого из N запросов:

1. Открывается новое TCP-соединение (keep-alive не переиспользуется —
см. «Решения и допущения»).

2 Засекается time.perf_counter().

3. Тело ответа читается полностью (resp.read()).

4. Секундомер останавливается, len(body) — реально скачанные байты.

В статистику идут только успешные запросы. Ожидания между ретраями в
среднее время не входят — они не про скорость канала.

Решения и допущения:
Здесь собраны все неочевидные места: ТЗ их не оговаривает, но они влияют
на результат.

Кэш
Заголовки Cache-Control: no-cache, no-store и Pragma: no-cache
отправляются в каждом запросе, но CDN/прокси может их проигнорировать.
Гарантии нет. Если нужен гарантированно «холодный» кэш — добавьте к URL
cache-buster:
python3 speedtest.py "https://example.com/file.bin?t=$(date +%s)"

Content-Length vs реальные байты
Content-Length не используется: он врёт при Transfer-Encoding: chunked,
при редиректах и при обрыве соединения. Считаем ровно len(body) —
фактически полученные байты.

Редиректы
urllib следует за редиректами автоматически. Время запроса включает
всю цепочку. Финальный URL не печатается, но при необходимости легко
добавить (resp.geturl()).

Требования

Python 3.8+ (time.perf_counter, argparse, urllib — все stdlib).

Сеть: доступ к указанному URL.

Никаких pip install не требуется.
